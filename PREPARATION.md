## 1. Паспорт приложения

**Название:** YouTube Studio Hub
**Что это:** приложение Imperal Cloud, которое подключает Google-аккаунты
(множественные) и даёт полный операционный обзор и управление YouTube-каналами
пользователя — контент, аналитика, управление каналом и генерация идей —
без функций монтажа/редактирования самого видео.

**Почему сейчас:** пользователь ведёт (или планирует вести) несколько
YouTube-каналов/аккаунтов и испытывает три конкретные боли (см. §2). Прямая
аналогия по архитектуре — уже работающая связка Content Strategy Hub +
Google Analytics Bluebee + Google Search Console Connector для блогов;
для YouTube в экосистеме Imperal сейчас **ничего не существует**
(проверено: `search_marketplace("youtube")` — 0 релевантных результатов).

**Связанное событие/цель:** нет привязки к внешнему pilot/событию — это
прямой запрос пользователя, расширяющий покрытие мультимедийных SEO-каналов
рядом с уже работающим блог-pipeline.

---

## 2. Проблема в человеческих словах

Когда **человек, ведущий несколько YouTube-каналов на разных Google-аккаунтах**
(например, для разных клиентских брендов, как ksrenovationgroup.com, g4s.md,
climtec.md — по аналогии с уже подключёнными в WordPress Hub сайтами),
сталкивается с **необходимостью ежедневно проверять состояние каждого
канала, публиковать метаданные и понимать, почему ролики не растут**,
ему приходится **вручную заходить в YouTube Studio по каждому каналу
отдельно, вручную читать Analytics-графики, вручную обновлять описания/теги/
превью, и отдельно вести список идей для следующих видео в заметках или
таблице**, из-за чего возникает **потеря времени на рутинную операционку,
отсутствие единой картины по всем каналам сразу и отсутствие связи между
тем, "что не работает" (аналитика) и "что снимать дальше" (идеи)**.

Существующие инструменты (сам YouTube Studio) не закрывают задачу, потому
что: (1) не агрегируют несколько каналов/аккаунтов в одном месте, (2) не
связывают аналитику конкретного видео с рекомендацией следующей темы, (3)
требуют раздельного открытия для каждого действия (метаданные, плейлисты,
комментарии, аналитика — разные экраны YouTube Studio).

---

## 3. Пользователь и роль

- **Основная роль:** владелец/менеджер нескольких YouTube-каналов
  (мультитенантный сценарий — по аналогии с site_profile в Content Strategy
  Hub, здесь: channel — своя сущность на аккаунт).
- **Не целевая роль в P0:** зритель/подписчик (нет функций для аудитории
  канала), монтажёр видео (никакого редактирования самого файла видео).

---

## 4. Главные боли — по приоритету (ответ пользователя)

1. **"Утомительно вручную публиковать/обновлять"** — операционная рутина:
   метаданные (заголовок/описание/теги/превью), плейлисты, комментарии,
   статус видео — разбросаны по интерфейсу YouTube Studio, по каждому
   каналу отдельно.
2. **"Не понимаю, почему видео не растут"** — аналитика не даёт ответа
   без интерпретации: сырые графики есть, but no synthesis связывающего
   просмотры/удержание/CTR с конкретными действиями.
3. **"Не знаю, о чём снимать"** — идеи контента (в самом низком приоритете,
   но явно нужны) — SEO/keyword-driven предложения тем, по аналогии с
   `discover_opportunities` в Content Strategy Hub, только для видео-формата.

## 5. Границы: делает / не делает

### Делает (полное покрытие, кроме монтажа — по явной формулировке пользователя):

- **Множественные Google-аккаунты** и множественные каналы на каждый
  аккаунт (OAuth per-account, как Google Drive/Analytics Connector).
- **Content/метаданные (My Content):** список видео канала, детальный
  просмотр видео, редактирование метаданных (title/description/tags/
  category/privacy status/thumbnail), просмотр/управление плейлистами.
- **Analytics:** отчёты YouTube Analytics API (просмотры, watch time,
  удержание аудитории, подписчики, топ-видео, источники трафика,
  демография) — на уровне канала и на уровне отдельного видео.
- **Channel Management:** настройки канала (описание, ключевые слова,
  branding — насколько разрешает API), список/модерация комментариев
  (ответить/скрыть/удалить/пометить спамом — `commentThreads`/`comments`
  API), плейлисты (создание/редактирование/удаление, не самого видео).
- **Content Ideas:** SEO-driven генерация идей — на основе трендовых
  запросов (можно переиспользовать DataForSEO Connector/веб-поиск) +
  разрывов в текущем контенте канала (какие темы уже покрыты по
  заголовкам/тегам существующих видео, какие нет).

### НЕ делает (явный отказ, зафиксированный пользователем):

- **Редактирование/обрезка самого видеофайла** — никакого монтажа,
  никакой перекодировки, никакой работы с видеодорожкой.
- **Загрузка/публикация нового видео** — явный ответ пользователя:
  "публикация видео не нужна". Значит `videos.insert` (upload) — вне
  границ P0. Управление уже существующими видео (метаданные) — да,
  публикация нового файла — нет.

### Риски / действия, требующие явного подтверждения:

- Удаление комментария, удаление плейлиста, смена privacy status видео на
  `private`/`unlisted` при массовом изменении — деструктивные операции,
  обязательный confirm/preview-apply паттерн (как в WordPress Hub bulk-tools).
- Никаких утверждений вида "это видео гарантированно вырастет, если..." —
  Analytics/Ideas дают данные и наблюдения, не гарантии.

## 6. Данные, конфиденциальность и интеграции

### Источники данных (все — реальные Google API, проверено по документации):

| API | Назначение | Статус |
|---|---|---|
| YouTube Data API v3 | каналы, видео, плейлисты, комментарии, метаданные | `available` |
| YouTube Analytics API v2 (`reports.query`) | отчёты по каналу/видео (views, watch time, retention, traffic sources, demographics) | `available` |
| DataForSEO Connector (уже установлен) | keyword/trend-сигналы для Content Ideas | `available`, переиспользуем существующее приложение |

### OAuth-скоупы (сверено напрямую с developers.google.com, не придумано):

- `https://www.googleapis.com/auth/youtube.readonly` — базовое чтение
  каналов/видео/плейлистов. Также **обязателен** для `youtubeAnalytics.reports.query`
  (Google теперь явно требует этот скоуп для Analytics-запросов, не
  отдельный `yt-analytics.readonly` сам по себе — подтверждено на странице
  `reports/query` reference: "API requests to this method now require
  access to the `youtube.readonly` scope").
- `https://www.googleapis.com/auth/youtube.force-ssl` — запись метаданных
  видео, плейлистов, ответы на комментарии, модерация комментариев (нужен
  полный write-скоуп для этих операций, `youtube.readonly` их не покрывает).
- `https://www.googleapis.com/auth/yt-analytics.readonly` — держим как
  явно задекларированный скоуп рядом с `youtube.readonly` для Analytics
  reports (стандартная практика Google-примеров — оба скоупа вместе).
- **НЕ запрашиваем** `yt-analytics-monetary.readonly` (revenue-данные) —
  не упомянуто пользователем как нужное, лишний скоуп повышает
  consent-friction и требует OAuth verification review у Google.
- **НЕ запрашиваем** `youtube.upload` — публикация видео явно не нужна.

### Хранение / tenant isolation:

- По аналогии с Google Drive/Analytics Connector: коллекция
  `youtube_accounts` (OAuth-токены, per-user, per-account), `youtube_channels`
  (кэш списка каналов на аккаунт, обновляется on-demand), никаких видео-файлов
  не храним — только метаданные и ссылки на реальный YouTube.
- Комментарии/аналитика читаются on-demand, не кэшируются бессрочно
  (только последний снапшот для UI, как Page Speed Insights делает со
  снапшотами).

## 7. P0 — минимальный законченный полезный путь

**Главный use case:** пользователь подключает Google-аккаунт → видит список
своих каналов на всех подключённых аккаунтах → кликает канал → видит его
контент, может открыть любое видео и посмотреть/поправить его метаданные,
посмотреть аналитику канала и получить готовые идеи для следующего видео.

**Без чего результат невозможен:**
1. OAuth-подключение Google-аккаунта (множественное).
2. Список каналов по всем подключённым аккаунтам.
3. Detail-вью канала: My Content (список видео) → detail видео (метаданные,
   базовая статистика).
4. Хотя бы один реальный Analytics-отчёт на уровне канала (views/watch
   time за период).
5. Хотя бы одна форма Content Ideas (даже упрощённая — на основе тегов
   уже существующих видео + trend-сигнал).

**Сознательно исключено из P0:** полноценный Channel Management (branding,
глубокая модерация комментариев с bulk-действиями) и полный набор Analytics
dimensions — это следующий срез после того, как базовый путь подтверждён
live.

```

ЦЕНТРАЛЬНАЯ ОБЛАСТЬ

  ↓ клик по каналу в сайдбаре
┌─────────────────────────────────────┐
│ {Channel Name}                       │
│ {ссылка на канал}                    │
├─ Tabs ────────────────────────────────┤
│ [My Content (X)] Analytics  Channel Management  Content Ideas │
├───────────────────────────────────────┤
```

по аналогии с существующим паттерном `list_queue`/бейджей в других
приложениях экосистемы.

## 9. Ценность и измеримый результат

- Время на еженедельный "channel health check" по всем каналам — из
  N отдельных заходов в YouTube Studio в один заход в Imperal.
- Доля видео с заполненными/оптимизированными метаданными (не "Untitled"/
  пустое описание) — измеримо через `list_videos` + сравнение полей.
- Число реализованных Content Ideas (idea → фактически снятое видео) —
  аналог `queue` lifecycle из Content Strategy Hub, но без фазы "публикация".
- Неуспех: если после MVP пользователь продолжает открывать сам YouTube
  Studio для рутинных задач вместо этого приложения — сигнал, что
  P0-набора функций недостаточно.

## 10. Открытые вопросы / решения, принятые ПЕРЕД кодом

1. **Один OAuth-провайдер на несколько каналов.** YouTube Data API
   возвращает `channels.list(mine=true)` обычно один канал на Google-аккаунт
   (Brand Accounts дают доступ к нескольким каналам под одним логином).
   Решение: `youtube_channels` хранит запись на каждый канал, видимый
   аккаунту — не предполагаем ровно 1:1 аккаунт↔канал.
2. **`ui.Tabs` vs Button+`ui.Call` паттерн.** В Brand Strategy Hub `ui.Tabs`
   был сознательно заменён на Button+`ui.Call`, т.к. `ui.Tabs` "unproven"
   нигде в живых панелях экосистемы. Решение для YouTube Studio Hub: тоже
   используем Button+`ui.Call(tab=...)` — тот же проверенный паттерн, а не
   первый эксперимент с `ui.Tabs` в проде.
3. **Content Ideas — reuse vs own logic.** DataForSEO Connector уже даёт
   keyword volume/trends. Решение: строим Content Ideas как собственную
   функцию внутри YouTube Studio Hub, которая ПРИНИМАЕТ query-сигналы
   (переданные Webbee из DataForSEO, тот же контракт, что
   `discover_opportunities` в Content Strategy Hub принимает `queries` от
   Google Search Console) — не встраиваем прямую HTTP-интеграцию с чужим
   приложением.
